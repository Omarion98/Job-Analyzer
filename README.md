# AI Career Copilot

[![Career Copilot CI](https://github.com/Omarion98/Job-Analyzer/actions/workflows/ci.yml/badge.svg)](https://github.com/Omarion98/Job-Analyzer/actions/workflows/ci.yml)

**Upload a CV, add a job description, and get a clear breakdown of matching skills, gaps, and what to prepare for next.**

AI Career Copilot is a full-stack application I built to explore how large language models can support job preparation—and how to turn an AI prototype into a usable software application.

## 🎬 Live Demo

[▶️ Watch AI Career Copilot in Action](https://youtu.be/GUYSAvDR8oQ)

## What it does

1. **Compare:** Upload a PDF CV and paste a job description.
2. **Understand the gaps:** Review a match score, strong matches, partial matches, and missing skills.
3. **Prepare:** Get suggested interview topics, learning priorities, and a short overall assessment.

The app also supports analyzing a job description on its own.

> **Note:** Results are generated by an LLM and are intended for personal exploration and interview preparation—not as verified hiring predictions or automated employment decisions.

## What I built and learned

This started as an AI application idea, but I wanted to work on the engineering around it too:

- **Full-stack development:** Built the interface with React/TypeScript and the API with Python/FastAPI.
- **Reliable AI integration:** Used structured model output and Pydantic validation instead of sending unchecked free-form text to the frontend.
- **Flexible local/cloud setup:** Made CV extraction switchable between PyPDF and Azure AI Document Intelligence. The working LLM integration uses local Ollama with Gemma 3 4B.
- **Cloud deployment and security:** Deployed Dockerized frontend/backend services to Azure Container Apps, used a private Container Registry, and configured Managed Identity and role-based access.
- **Monitoring and CI:** Added OpenTelemetry tracing to measure individual processing stages and a GitHub Actions workflow to check and build the application.

**Tech stack:** Python · FastAPI · React · TypeScript · Ollama/Gemma 3 · Pydantic · Docker · Azure · OpenTelemetry · GitHub Actions

## How it works

The **current runnable version is local**: the frontend sends the CV and job description to FastAPI, which extracts text, calls Gemma through Ollama, validates the response, and returns the assessment.

![Current local application architecture](docs/diagrams/local-architecture.svg)

### Cloud engineering: previously deployed on Azure

I also deployed and tested the frontend and backend on Azure Container Apps. The Azure version used Document Intelligence for CV extraction, Managed Identity for service authentication, and Application Insights for request tracing.

![Architecture of the previously deployed Azure components](docs/diagrams/azure-architecture.svg)

**Current status:** The Azure environment is paused because the free trial ended. Full cloud-hosted LLM matching was not completed; the Azure OpenAI provider is still a placeholder. **The application continues to work locally**, without an Azure subscription.

## Run it locally

You need **Python 3.11+**, **Node.js/npm**, and [Ollama](https://ollama.com/). These commands use Windows PowerShell.

**1. Clone the project and download the model**

```powershell
git clone https://github.com/Omarion98/Job-Analyzer.git
cd Job-Analyzer
ollama pull gemma3:4b
```

Make sure Ollama is running (start `ollama serve` if needed).

**2. Start the backend**

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

$env:CV_EXTRACTOR="pypdf"
$env:LLM_PROVIDER="ollama"
$env:OLLAMA_BASE_URL="http://127.0.0.1:11434"
$env:OLLAMA_MODEL="gemma3:4b"

uvicorn main:app --reload --port 8000
```

**3. Start the frontend** in a second terminal, from the repository root:

```powershell
cd frontend
npm ci
```

Create `frontend/.env.local` with:

```dotenv
VITE_API_URL=http://localhost:8000
```

Start the interface:

```powershell
npm run dev
```

Visit **http://localhost:5173**. For detailed configuration, API routes, and non-Windows setup notes, see [Engineering notes](docs/ENGINEERING.md).
